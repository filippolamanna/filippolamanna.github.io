Run Form Tracker

Two small sensor pods, one above each ankle, that measure how evenly your left and right legs share the work.

ROLE
Solo, hardware and software
YEAR
2026
STACK
C++ · ESP32-C3 · Python · NumPy · pandas
STATUS
Software done, hardware next

01 · WHAT IT DOES

Running watches tell you pace and step rate, but not whether your left and right legs do the same work. That imbalance can point to injury risk or bad form.

Each pod records leg motion during a run. Afterwards a Python program lines up the two recordings and reports, for each leg, how long the foot stays on the ground, stride timing, impact and how symmetrical the two sides are. The software is finished; the hardware is waiting to be assembled and tested.

02 · HOW IT WORKS

  • Each pod is an ESP32-C3 microcontroller with a 6-axis motion sensor and a microSD card, on a small battery.
  • The sensor records 208 times a second into its own buffer, and the chip copies it to the card in batches, so slow card writes never lose samples.
  • The pods have no radio link. Three two-footed jumps at the start and end of a run leave matching impact spikes in both recordings, which the software uses to align them and correct for clock drift.
  • Strides are found from the rotation of the lower leg: the peak in mid-swing, then the moments the foot lands and leaves the ground. No machine learning.
  • For each leg it computes ground contact, swing, flight and stride time, impact peak and stride-time variability, then a symmetry index comparing the two sides.
  • Different LED blink patterns flag a sensor or card failure, so a pod never looks like it is recording when it isn't.

05 · HOW IT WAS BUILT

Built with AI-assisted development (Claude Code). I chose the goal (left and right asymmetry, cadence and ground contact time), the hardware, and the no-radio design with the jump ritual for syncing. The model wrote the firmware, the Python analysis package and its tests from a written spec and plan.

The hard part is still ahead: so far it has only run on synthetic data. The real test is assembling the pods and checking the results against a walk with a known number of steps.

06 · WHAT I LEARNED

  • Decide how the data is stored first. Raw, self-describing files keep options open, such as training models on them later.
  • Choosing the simplest hardware and fixing timing in software avoided a whole class of wireless sync problems.
  • Synthetic signals catch logic bugs, but only real hardware will show whether the thresholds are right.
